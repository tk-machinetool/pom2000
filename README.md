# ポムの樹 2,000円参考チェッカー v0.4

食べたい商品を1品以上固定し、その商品を必ず含めたまま、オムライスを含む税込2,000円以上の注文へ最小追加で近づける非公式Webアプリです。一次情報で一点価格を確認できた項目だけを計算に使います。価格・取扱商品・セット内容は店舗により異なります。

## 開発

```bash
npm install
npm run dev
npm test
npm run typecheck
npm run build
```

Viteの `base` は `./` です。`dist/` をGitHub Pagesなどの静的ホスティングへ配置できます。ログイン、バックエンド、外部APIは不要です。

## 正本

アプリは次のデータを直接importします。コピーを作らないため、実装データとの同期作業は不要です。

- `handoff/menu-data.json`
- `handoff/CODEX_HANDOFF.md`
- `handoff/ACCEPTANCE_TESTS.md`
- `handoff/SOURCE_LEDGER.md`

## 価格データ更新手順

1. `handoff/SOURCE_LEDGER.md` にある一次情報を再確認し、URL・公開日・適用日・確認日を記録する。
2. `handoff/menu-data.json` の `sources` を更新する。新しい根拠は既存価格を黙って上書きせず、履歴または `supersedes` 関係を残す。
3. `menu` へ入れるのは税込の一点価格が確認できた項目だけとする。`priceFrom` や「〜」価格、未確認のサイズ差、単品価格が不明な差額情報から価格を合成しない。
4. 将来販売の商品は `status: official-future` と `start` を設定する。開始日時はAsia/Tokyoで判定される。
5. 終了日が不明な期間限定商品は終了日を推測せず、必要に応じて `reviewAfter` を設定する。期限後も掲載する場合は、再確認した日を `revalidatedOn` に記録する。
6. ランチ限定価格は `menuContext: lunch`、施設・店舗固有価格は `facilityOfficialEvidence` に置く。店舗固有価格を既定の参考価格へ移さない。
7. セット商品は公式資料に税込確定価格がある場合だけ `bundle` として登録し、内容を推測して分解しない。適格判定には `containsOmurice` を明示する。
8. `npm test` と `npm run build` を実行し、現在・将来境界・鮮度期限・上位20件の回帰を確認する。

## 探索仕様

- トップの部分一致検索から1品以上を固定し、全候補へ固定数量を必ず引き継ぐ
- 公式データとは分離した「仮ドリンク」を初期400円で追加でき、利用者が整数価格を変更できる
- 仮価格を含む候補は「予想合計」「超過見込み」と表示し、店頭確認の注意を必ず併記する
- 固定注文が2,000円未満なら不足額を表示し、オムライスがなければオムライスを含む追加候補だけを表示
- 固定注文だけで2,000円以上かつオムライスを含む場合は、追加なしを1位にする
- 1商品あたり最大2個、合計最大4品のbounded multiset search
- 並び順だけが異なる同一注文は重複排除
- 2,000円未満と `containsOmurice=false` だけの注文は適格判定段階で除外
- 固定商品候補は、超過額、追加品数、重複数、既知のオムライスサイズ、商品IDの順で安定ソート
- 1人向け、2人向け、金額最優先のプリセットは下段の補助機能として提供

仮ドリンクは実行時にのみ生成され、`handoff/menu-data.json` には保存しません。価格区分は「公式掲載参考価格」「仮価格」「店頭入力価格」を分離し、公式掲載参考価格も店舗での価格を保証しません。
